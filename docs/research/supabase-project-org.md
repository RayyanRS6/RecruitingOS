FACTS:
1. DELETE A PROJECT (dashboard). Page: https://supabase.com/docs/guides/platform/delete-project, section 'How to delete a project' > 'Via dashboard'. Steps printed verbatim: '1. Navigate to your project's Settings > General > Delete project  2. Click Delete Project  3. Enter your project name exactly as it appears to confirm  4. Review the confirmation dialog and click Delete'. The page links the Settings > General screen as https://supabase.com/dashboard/project/_/settings/general (anchor #delete-project). The exact wording inside the confirmation dialog is not printed on the page; only the requirement to type the project name exactly and click 'Delete'.

2. DELETE A PROJECT (irreversibility and timing). Same page states deletion is 'a permanent and irreversible action' and 'We cannot recover deleted projects. All data, backups, and configurations are permanently removed.' Section 'After deletion': 'Your project URL will no longer be accessible, DNS records will be cleaned up (may take up to 24 hours to fully propagate), Billing for this project will stop immediately, You cannot recover or restore the project'. Section 'What gets deleted' lists the Postgres database, Edge Functions and source, Storage bucket files, automated backups and PITR snapshots, Auth user data and sessions, Realtime subscriptions, API keys/service role keys/webhooks, custom domains and SSL certificates.

3. DELETE A PROJECT (other routes). Same page: CLI 'supabase projects delete <project-ref>' and Management API 'curl -X DELETE https://api.supabase.com/v1/projects/<project-ref>'. CLI reference https://supabase.com/docs/reference/cli/supabase-projects-delete prints usage 'supabase projects delete [ref]' with no flags and no description. Management API reference https://supabase.com/docs/reference/api/v1-delete-a-project: 'delete /v1/projects/{ref}', path param 'ref' (Project ref), requires OAuth scope 'projects:write' or fine-grained token permission 'project_admin_write'; 200 response returns the deleted project's id, ref, and name.

4. DELETE A PROJECT (who can). https://supabase.com/docs/guides/platform/access-control permissions table: Project Management > Delete = Owner yes, Administrator yes, Developer no, Read-Only no. Project Management > Transfer = Owner only. Organization Management > Delete = Owner only. Organization Management > Update = Owner only. Subscription > Update = Owner and Administrator. The delete-project page's 'Protective measures to consider' > 'Enable access controls' says: 'Set up role-based access controls to limit deletion permissions' and 'Require multi-factor authentication (MFA) for sensitive operations'.

5. PAUSE INSTEAD OF DELETE. https://supabase.com/docs/guides/platform/delete-project section 'Alternative: Pause your project': 'Only Free Projects can be paused at this time.' Path printed: 'Settings > General > Project availability' then 'click Pause Project' (link https://supabase.com/dashboard/project/_/settings/general). https://supabase.com/docs/guides/platform/free-project-pausing: Free projects are auto-paused after 'low activity over a 7-day period'; 'Projects under a paid plan cannot be paused and are not subject to automatic pausing for inactivity'; restore steps: '1. Open the Supabase Dashboard (https://supabase.com/dashboard/organizations) 2. Select the organization, followed by the paused project 3. Click Resume project and confirm'; 'Once the project is paused, there is a 1-year window to restore the project on the platform from within Supabase Studio.' https://supabase.com/docs/guides/troubleshooting/pausing-pro-projects-vNL-2a: 'Pro-Projects at the moment cannot be paused.' https://supabase.com/docs/guides/platform/billing-faq: 'Paused projects do not count towards your quota.'

8. MOVE A PROJECT TO ANOTHER ORG INSTEAD OF DELETING. https://supabase.com/docs/guides/platform/project-transfer: transfers start from the project's general settings, link https://supabase.com/dashboard/project/_/settings/general, with a confirmation modal. Requirements: you must be Owner of the source organization; at least a member of the target organization; no active GitHub integration connection; no project-scoped roles pointing at the project (Team/Enterprise); no log drains configured. 'Project transfers are only transferring your projects across an organization and cannot be used to transfer between different regions.' Transferring from a paid plan to a Free Plan org 'could trigger downtime (1-2 minutes)'; the Free Plan two-project limit applies to the receiving org. 'The source organization will still be charged for the usage up until the transfer'; the target org is charged from the next billing cycle. The exact transfer button/section label is not printed on the page. https://supabase.com/docs/guides/platform/billing-faq also confirms: 'Yes, you can transfer your projects to another organization.'

COMPUTE PRICES AND PRO CREDIT. https://supabase.com/docs/guides/platform/compute-and-disk table: 'Nano | $0 | $0 | Shared | Up to 0.5 GB | 500 MB' and 'Micro | $0.01344 | ~$10 | Shared | 1 GB | 10 GB'; 'The following table describes the base instances, Nano (free plan) and Micro (paid plans)'; 'You cannot launch Nano instances on paid plans, only Micro and above'; 'In paid organizations, Nano Compute are billed at the same price as Micro Compute.' https://supabase.com/docs/guides/platform/manage-your-usage/compute: 'Compute is charged by the hour'; 'Paid plans include $10 in Compute Credits, which cover one project running on the Micro/Nano Compute size or portions of other Compute sizes'; credits reset monthly and do not carry over; 'Each project you launch increases your monthly Compute costs'; billing stops when a project is deleted mid-month. https://supabase.com/docs/guides/platform/billing-faq: 'Each paid organization comes with $10 in Compute Credits to cover one project on the default compute size' and 'Additional projects start at ~$10 a month (billed hourly).' https://supabase.com/pricing: 'Pro - from $25/month'; 'Pro and Team plans include $10/month in compute credits'; Micro listed at '$10' per month. Net: on a Pro org the first Micro project is covered by the $10 credit; a second Micro project costs about $10/month (730 h x $0.01344), and Compute is outside the Spend Cap.

15. IMPLICATION FOR THE ITS SETUP. Because 'recruiting-os-staging' runs on Micro and Nano is the only Free-plan size, the 'Identified Talent Solutions' organization must be on a paid plan (Pro or higher). Whether the unused Ohio project costs anything depends on which organization it sits in: in a separate Free Plan organization it runs on Nano at $0 (and counts toward the two active free projects); if it is inside the paid organization it is billed hourly as Micro-priced compute beyond the single $10 credit. Deleting it stops billing immediately per the delete-project page.
