ADMIN CONSENT - v2 endpoint for multi-tenant apps (v2-admin-consent, ms.date 2023-11-08): 'https://login.microsoftonline.com/{tenant}/v2.0/adminconsent?client_id=...&scope=...&redirect_uri=...&state=...'. tenant: 'Can be provided in GUID or friendly name format OR generically referenced with organizations... 29. MULTI-TENANT CONVERSION AND CONSENT (howto-convert-app-to-be-multi-tenant, ms.date 2024-11-13): 'By default, web app/API registrations in Microsoft Entra ID are single-tenant upon creation. To make the registration multitenant... select the **Authentication** pane and navigate to the **Supported account types** section. Change the setting to **Accounts in any organizational directory**.' App ID URI 'for multitenant apps it must be globally unique across all tenants' (pattern like https://contoso.onmicrosoft.com/myapp), otherwise 'setting an application as multitenant fails.' Requests go to 'https://login.microsoftonline.com/common' (or '/organizations' 'if your application doesn't support Microsoft personal accounts'). First sign-in from another tenant: 'Microsoft Entra ID asks them to consent to the permissions requested by the application. If they consent, then a representation of the application called a *service principal* is created in the user's tenant'. 'App-only permissions always require a tenant administrator's consent.' 'Certain delegated permissions also require a tenant administrator's consent.' Admin sign-up: 'consider adding a button or link where the admin can initiate the action... the usual OAuth2/OpenID Connect authorization request that also includes the prompt=consent query string parameter. After the admin consents... subsequent sign-in requests don't need the prompt=consent parameter... no other users in the tenant are prompted for consent.' 'If an application requires admin consent and an admin signs in without the prompt=consent parameter being sent, when the admin successfully consents to the application it applies **only for their user account**.' Customer tenants can disable user consent: 'In **Enterprise applications** > Consent and permissions, check the **Do not allow user consent** option.' howto-update-permissions: 'Multi-tenant apps in customer's tenants: User sees new consent prompts on their next sign-in attempt. If the permissions only require user consent, the user can grant consent. If the permissions require admin consent, the user must contact their administrator to grant consent.'
