# @ros/evals

The AI evaluation runner (`docs/11-evaluation-framework.md`). Suites are synthetic fixtures plus assertions in `src/suites.ts` (the job builder's in `src/intake-suite.ts`, one turn of the AI interview in `src/chat-suite.ts`, a whole interview in `src/conversation-suite.ts`); the runner in `src/runner.ts` drives them through the same prompts the product uses and scores them against `thresholds.json`.

- `pnpm eval` from the repository root runs every suite on the fake provider: it proves the harness, the schemas and the code-side rules (quote checks, the licence rule, the chat's ladder, the offer of a person), not the prompts.
- `AI_PROVIDER=anthropic ANTHROPIC_API_KEY=<key> pnpm eval` runs the real models. The key is entered for the shell session on a trusted machine and never stored in the repository.
- `pnpm eval --suite screen.conversation` runs one suite; `--suite resume,triage` runs every suite of each family. A name that chooses no suite fails the run. A whole run (no `--suite`) also fails when a suite has no entry in `thresholds.json` or an entry there names no suite, so a suite added or renamed goes into both.
- The two readings that score (`triage.assess`, the CV reading, and `screen.assess`, the AI interview's scorecard) are given their input exactly as the app builds it (`scoringInput` and `scorecardInput` in `@ros/agents`), through `src/scoring-inputs.ts`: name, email, phone, street address and links hidden, earlier applications never sent. Each is read three times and the middle answer kept, by the app's own `readingsOutcome` and `scorecardReadings`. The model writes findings and quotes only; every number the suites compare (the CV score, the interview score, their bands) is worked out by the app's own code from those findings.
- `triage.redaction` and `screen.redaction` check that a CV or an interview full of personal details sends the model none of them, and the `earlier_rejection` twin pair checks that an earlier rejection at the same company leaves the model's input identical. `src/scoring-inputs.test.ts` runs these input checks with the unit tests, with no model.
- `score.rules` and `triage.fairness_rules` call no model and also run with the unit tests (`src/score-suite.test.ts`). `score.rules` holds the CV score to its rules: a must-have weighs 4 and a skill 3, 2 or 1, shown earns all and partly shown half, a must-have their own quoted words show is not met holds the number at 54, and 100 never stands beside a must-have that is not shown. `triage.fairness_rules` holds that showing more never lowers the score, that the score moves only with the findings (never with a reading's words or the order the readings came back in), and that every answer on the form reaches the reading as a sentence that counts as the candidate's own words.

Every run writes `results/<date>-<time>-<provider>.json`, in a folder git ignores. The full procedure is in `docs/11-evaluation-framework.md` under "The real-model run".
